# Northbridge Software Ltd — Buy-Side Due Diligence (Transaction Analytics)

A self-directed simulation of a buy-side financial due diligence exercise on a
fictional UK B2B SaaS company. It runs from raw, messy data-room extracts through
cleansing, reconciliation and analysis to an investor findings memo, mirroring the
work a Transaction Analytics team does on an M&A deal.

The data is synthetic and generated by a seeded script in this repo. This is not
client work and does not use any real company's data.

## The scenario

A mid-market private equity fund is considering acquiring Northbridge Software Ltd,
a subscription software business selling to small and mid-sized companies, with
revenue of roughly £40m a year. The seller's adviser has shared a data-room extract.
The exercise takes the analyst role on the buy-side team and answers the questions an
investor actually cares about:

- Is the revenue real, and does it tie back to the management accounts?
- How much is recurring and predictable versus one-off?
- Are customers staying, growing, or leaving?
- Is the business dangerously dependent on a few large customers?
- Where does margin actually come from?
- What explains the change in revenue year on year?
- What should change the price or the deal structure?

## The data room

Six tables spanning monthly data from January 2022 to December 2025.

| Table | Grain | Notes |
|---|---|---|
| `customers` | one per customer | industry, region, size band, channel, account manager |
| `products` | one per SKU | product line and recurring/one-off flag |
| `subscriptions` | one per contract line | price, term, discount, start/end |
| `invoices` | one per billing event | the transactional truth, including credit notes |
| `costs` | month × product line | cost of delivery, for gross margin |
| `management_accounts` | month | the reported P&L, the reconciliation target |

## Reproducing the data

```bash
pip install -r requirements.txt
python data/generator/generate_data.py
```

The generator uses a fixed random seed, so the output is identical on every run.
It builds in realistic commercial behaviour (acquisition growth and seasonality,
churn that varies by cohort and segment, upsell and downgrade, renewal price
increases, size-based discounting) and a set of deliberately planted issues that
the analysis is designed to surface.

## Method

The exercise runs in steps: build the data, profile and cleanse it, reconcile the
cleaned figures to the management accounts, run the core analyses (revenue quality,
concentration, cohort retention, net and gross revenue retention, an ARR bridge,
margin and segment cuts), assemble a databook and a dashboard, and write the memo.
Every cleaning decision is logged in `docs/` so each adjustment is explainable, the
same standard a real deal holds.
